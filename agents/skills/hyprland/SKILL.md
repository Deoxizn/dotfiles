## 1. Lua conversion status & timeline (IMPORTANT)

- **0.55 (May 2026)**: Lua became the primary config format. If `hyprland.lua`
  exists, it is loaded; otherwise the legacy `hyprland.conf` is still used.
- **0.56 (Jul 2026)**: Lua is the default everywhere; the wiki only documents
  Lua (legacy pages under the 0.54 version selector).
- **hyprlang is deprecated**: supported for roughly 1–2 releases after 0.55.
  It will be **dropped** (expected around 0.57, ~Aug 2026). No new features
  are added to hyprlang.
- The language choice (`.lua` vs `.conf`) is decided **once at startup** and
  does not change on reload. Restart Hyprland to switch.
- New in Lua that `.conf` never had: `hl.timer`, `hl.on(...)` event callbacks,
  `hl.get_windows()/get_monitors()` queries, custom layouts via `hl.layout.register`,
  and the `hyprctl eval` / Lua REPL for live testing.
- This machine is already **fully Lua** — default target for new config work.
  Legacy `.conf` work is only for troubleshooting old configs / other machines.

## 2. Config file model

- Main config: `$XDG_CONFIG_HOME/hypr/hyprland.lua` (here: `~/.config/hypr/hyprland.lua`).
- Override path: `hyprland -c /path/to/config.lua` (or `--config`).
- Config **reloads automatically on save**. Force with `hyprctl reload`.
- If no config exists, Hyprland generates an example containing
  `hl.config({ autogenerated = true })` — removing that line clears the yellow warning.
- `require()` pulls in other files. Use `/` or `.` as separators,
  relative to `~/.config/hypr/` (or absolute paths / wildcards):
  `require("hypr.bindings")`, `require("default.hypr.omarchy")`, `require("awesomeconf/keybinds")`.
- **Lua config runs arbitrary code on your machine.** Trust what you require.
- **Error behavior** (from the wiki):
  - Fundamental syntax error → Hyprland **refuses to reload** and pops an error.
  - Runtime Lua error (e.g. calling a nil) → aborts the current file, pops an error.
  - Runtime Hyprland type error (e.g. passing a string where a table is expected) → continues, pops an error.
  - Errors in async handlers (keybind functions) → logged, do **not** kill the session.
  - Infinite loops / runaway scripts are killed by a built-in timeout guard.
- Non-Lua files in `~/.config/hypr/` are separate tools, **not** Hyprland config:
  `hyprpaper.conf`, `hyprlock.conf`, `hypridle.conf`, `hyprsunset.conf`,
  `envs.conf`, `xdph.conf`. Editing them does not trigger `hyprctl reload`.

### Omarchy bootstrap (this system)

`hyprland.lua` starts with:

```lua
dofile((os.getenv("OMARCHY_PATH") or "/usr/share/omarchy") .. "/default/hypr/bootstrap.lua")
```

Then `require("default.hypr.omarchy")` loads Omarchy defaults, followed by user
files that are loaded **after** the defaults so overrides win:

```lua
require("hypr.monitors")   -- ~/.config/hypr/monitors.lua
require("hypr.input")      -- input.lua
require("hypr.bindings")   -- bindings.lua
require("hypr.looknfeel")  -- looknfeel.lua
require("hypr.autostart")  -- autostart.lua
```

- Omarchy ships helper globals in `~/.config/hypr` config scope: `o.bind(...)`,
  `o.window(...)`, `o.launch(...)`, `o.bind_toggle(...)`, `o.notify(...)`,
  `o.launch_on_start(...)`, `o.launch_webapp(...)`. Definitions live in
  `/usr/share/omarchy/default/hypr/helpers.lua` (read-only reference).
- `o.bind(keys, description, dispatcher, opts)` wraps `hl.bind` and wraps
  launchers in `uwsm-app`. `dispatcher` can be a string (shell command), an
  `hl.dsp.*` dispatcher, or a table: `{ omarchy = "terminal" }`,
  `{ launch = "cmd" }`, `{ focus = "...", launch = "..." }`, `{ webapp = "https://..." }`,
  `{ tui = "..." }`.
- `o.window(match, rules)` wraps `hl.window_rule`: a string match becomes
  `match.class`, or pass a match table.
- Global flags (set **before** `require("default.hypr.omarchy")`):
  - `omarchy_default_bindings = false` → disable all Omarchy default keybinds.
  - `omarchy_preinstalled_bindings = false` → disable app/webapp binds only.
- Reloading config with `bootstrap.lua` purges cached modules under
  `default.hypr`, `hypr`, `omarchy.current.theme` so changes reload cleanly.

The canonical signatures are in `/usr/share/hypr/stubs/hl.meta.lua`. Highlights:

```lua
-- grouped settings (one call, many categories)

  general = { gaps_in = 5, gaps_out = 20, border_size = 2, layout = "dwindle" },
  decoration = { rounding = 10, blur = { enabled = true }, shadow = { enabled = true } },
  animations = { enabled = true },
  input = { kb_layout = "us", touchpad = { natural_scroll = true } },
  misc = { force_default_wallpaper = 0 },

-- read a value back

-- environment variables

-- monitors

-- keybinds (see section 8)
hl.bind("SUPER + Q", hl.dsp.window.close(), { description = "Close window" })

-- rules (sections 5-7)
hl.window_rule({ name = "x", match = { class = "kitty" }, float = true })

hl.layer_rule({ match = { namespace = "waybar" }, blur = true })

-- events, timers, autostart
hl.on("hyprland.start", function() hl.exec_cmd("nm-applet") end)
hl.on("window.title", function(w) if w and w.title == "foo" then hl.dispatch(hl.dsp.window.float({ action = "set" })) end end)
hl.timer(function() print("hi") end, { timeout = 5000, type = "oneshot" })

-- animations
hl.curve("easeOutQuint", { type = "bezier", points = { {0.23, 1}, {0.32, 1} } })
hl.animation({ leaf = "windows", enabled = true, speed = 4.79, spring = "easy" })

-- queries (only inside Lua context)
local ws = hl.get_active_workspace()
local wins = hl.get_windows({ class = "kitty" })
local mon = hl.get_monitor("DP-1")
```

## 4. Rules model (all three rule types)

- Every rule takes a `match` table (the **props**, used to decide) plus
  **effect** fields (what happens). All props must match for the rule to fire.
- **Order matters**: rules are evaluated top to bottom; the **last match wins**.
- **Named rules** (have `name = "..."`) are evaluated before anonymous rules,
  and named rules take precedence. Only named rules can be toggled later via
  the returned handle.
- Rules return a handle: `rule:set_enabled(false)`, `rule:set_enabled(true)`,
  `rule:is_enabled()`.

## 5. Window Rules

```lua
hl.window_rule({
  name  = "move-kitty",
  match = { class = "kitty" },
  move  = {100, 100},
  animation = "popin",
})
```

### Match props

| Field | Type | Matches |
|---|---|---|
| `class`, `title` | RegEx | class / title (RE2 regex; prefix `negative:` to negate) |
| `initial_class`, `initial_title` | RegEx | as-set-at-open values |
| `tag` | name | window tag |
| `xwayland` | bool | XWayland windows |
| `float`, `fullscreen`, `pin`, `focus`, `group`, `modal` | bool | state flags |
| `fullscreen_state_client`, `fullscreen_state_internal` | int | 0 none / 1 maximize / 2 fullscreen / 3 both |
| `workspace` | id/name/selector | e.g. `"5"`, `"special:name"` |
| `content` | string | `none`/`photo`/`video`/`game` |
| `xdg_tag` | RegEx | window xdg tag (see `hyprctl clients`) |

Use `hyprctl clients` to inspect a window's real class/title/flags. Hyprland
uses Google's **RE2** regex (no backtracking); unsupported constructs fail to parse.

### Static effects (applied once at open)

`float`, `tile`, `fullscreen`, `maximize`, `fullscreen_state` (e.g. `"1 2"`),
`move` (monitor-local; e.g. `{100, 200}` or expressions), `size`
(e.g. `{800, 600}`), `center` (bool), `pseudo`, `monitor` (e.g. `"DP-1"` or
`"1 silent"`), `workspace` (e.g. `"5 silent"` or `"unset"`), `no_initial_focus`,
`pin` (only for floating), `group` (see below), `suppress_event`
(`"fullscreen" "maximize" "activate" "activatefocus" "fullscreenoutput" "x11configurerequest"`),
`content`, `no_close_for` (ms), `scrolling_width`.

Static rules only see `initial_title`/`initial_class`. To react to a later
title change, use an `hl.on("window.title", ...)` handler instead.

`move`/`size` expression variables (space-separated, monitor-local):
`monitor_w monitor_h window_x window_y window_w window_h cursor_x cursor_y` —
e.g. `move = {"window_w * 0.5", "(monitor_h / 2) + 17"}`.

### Dynamic effects (re-evaluated on property change)

`persistent_size`, `no_max_size`, `stay_focused`, `animation` (e.g. `"popin 80%"`),
`border_color` (color or `{ colors = {...}, angle = 45 }`, active/inactive pair allowed),
`idle_inhibit` (`none`/`always`/`focus`/`fullscreen`), `opacity`
(`"0.8"`, `"0.9 0.7"` active/inactive, `"1.0 0.8 0.9"` +fs; append `" override"`),
`tag` (`"+x"` set / `"-x"` unset / `"x"` toggle), `max_size`/`min_size` (vec2),
`border_size`, `rounding`, `rounding_power`, `allows_input`, `dim_around`,
`decorate`, `focus_on_activate`, `keep_aspect_ratio`, `nearest_neighbor`,
`no_anim`, `no_blur`, `no_dim`, `no_focus`, `no_follow_mouse`, `no_shadow`,
`no_wobble`, `no_shortcuts_inhibit`, `no_screen_share`, `no_vrr`, `no_auto_hdr`,
`opaque`, `force_rgbx`, `sync_fullscreen`, `immediate` (tearing), `xray`,
`render_unfocused`, `scroll_mouse`, `scroll_touchpad`, `confine_pointer`,
`tonemap` (`on`/`off`/`clamp`/`limited`), `no_xdg_drags`.

All dynamic effects are settable at runtime via `hyprctl setprop`.

### Group rule options (`group = "..."`)

space-separated: `"set"` (`"always"`), `"new"`, `"lock"` (`"always"`),
`"barred"`, `"deny"`, `"invade"`, `"override"`, `"unset"`. Bare `group = true`
is shorthand for `group = "set"`.

### Tag gotchas

- Dynamic tags end in `*`. The `tag` **effect** manipulates dynamic tags only.
- The `tagwindow` **dispatcher** manages static tags only.
- `match.tag` matches static and dynamic forms; `"term"` matches both
  `term` and `term*`, `"term*"` matches only the dynamic tag.

### Examples (real patterns)

```lua
-- float a terminal
hl.window_rule({ match = { class = "kitty" }, float = true, size = { 1600, 600 } })

-- dim + red border when fullscreen
hl.window_rule({ match = { fullscreen = true }, border_color = "rgb(FF0000)" })

-- opacity: active/inactive/fullscreen, exact
hl.window_rule({ match = { class = "kitty" }, opacity = "1.0 override 0.5 override 0.8 override" })

-- keep focus on password popups
hl.window_rule({ match = { class = "(pinentry-)(.*)" }, stay_focused = true })

-- send an app to a workspace
hl.window_rule({ match = { class = "zen|chromium" }, workspace = "1" })

-- toggle on the fly
local r = hl.window_rule({ name = "my-rule", match = { class = "kitty" }, border_size = 5 })
r:set_enabled(false)
```

## 6. Workspace Rules

```lua
hl.workspace_rule({ workspace = "1", monitor = "DP-1", layout = "scrolling", layout_opts = { direction = "right" } })
```

Keys: `workspace` (required), `monitor`, `layout` (`dwindle`/`master`/`scrolling`),
`layout_opts`, `default`, `default_name`, `persistent`, `on_created_empty`,
`gaps_in`/`gaps_out`/`float_gaps`, `border_size`, `decorate`, `no_border`,
`no_rounding`, `no_shadow`, `animation`. Returns a handle (`set_enabled`/`is_enabled`).
Inspect live rules with `hyprctl workspacerules`.

## 7. Layer Rules

Layer surfaces (bars, launchers, wallpapers) are not windows:

```lua
hl.layer_rule({ match = { namespace = "waybar" }, blur = true })
```

Match prop: `namespace` (RegEx; check `hyprctl layers`). Effects: `no_anim`,
`blur`, `blur_popups`, `ignore_alpha` (0–1), `dim_around`, `xray`, `animation`,
`order`, `above_lock` (non-zero renders above lockscreen; `2` = interactive),
`no_screen_share`. Returns a handle.

## 8. Keybindings & dispatchers

```lua
local mainMod = "SUPER"

hl.bind(mainMod .. " + Q", hl.dsp.window.close(), { description = "Close window" })
hl.bind(mainMod .. " + mouse_down", hl.dsp.focus({ workspace = "e+1" }))
hl.bind(mainMod .. " + mouse:272", hl.dsp.window.drag(), { mouse = true })
hl.bind("XF86AudioRaiseVolume", hl.dsp.exec_cmd("wpctl set-volume -l 1 @DEFAULT_AUDIO_SINK@ 5%+"), { locked = true, repeating = true })
hl.unbind("SUPER + SPACE")
```

- `hl.bind(keys, dispatcher, opts)`. `opts` include `description`, `locked`,
  `repeating`, `release`, `non_consuming`, `transparent`, `ignore_mods`,
  `mouse`, `long_press`, `submap_universal`, `click`, `drag`, `device`.
- `hl.dsp.*` namespaces: `exec_cmd`, `exec_raw`, `focus`, `window.*`
  (`close`, `kill`, `float`, `fullscreen`, `move`, `resize`, `swap`, `pin`,
  `center`, `tag`, `bring_to_top`, `cycle_next`, `set_prop`, ...),
  `workspace.*` (`toggle_special`, `rename`, `move`, `change_id`, ...),
  `group.*`, `cursor.*`, `layout`, `submap`, `exit`.
- Calling a dispatcher as a value builds it: `hl.dsp.window.close()` returns a
  dispatcher object; `hl.dsp.exec_cmd("firefox")` wraps a command string.
- `hyprctl dispatch` accepts the same Lua dispatcher syntax:
  `hyprctl dispatch 'hl.dsp.window.tag({ tag = "+code" })'` (works on 0.56.2 —
  earlier syntax like `hyprctl dispatch moveactive` is legacy and should NOT be
  used on this machine).
- `define_submap(name, ...)` for submaps.
- Omarchy: inspect current binds with `omarchy menu keybindings --print`.
  When re-binding an existing key, `hl.unbind(...)` the old one first and tell
  the user what it used to do.

## 10. Legacy hyprlang (.conf) troubleshooting & migration

Use for old configs (pre-0.55) and to read/convert files still in `.conf` form.

### Old-syntax cheat sheet

```conf
$mainMod = SUPER            # variables (also ${var} interpolation)

monitor = HDMI-A-1, 1920x1080@60, 0x0, 1      # output, mode, pos, scale
monitor = DP-1, preferred, auto, 1.33

exec-once = waybar          # autostart
env = XCURSOR_SIZE,24

general {
    gaps_in = 5
    gaps_out = 20
    border_size = 2
    col.active_border = rgba(33ccffee) rgba(00ff99ee) 45deg
    layout = dwindle
}

decoration { rounding = 10
    blur { enabled = true }
}
animations { enabled = true }
bezier = easeOutQuint, 0.23, 1, 0.32, 1
animation = windows, 1, 4, default, popin 80%

input { kb_layout = us }

bind = SUPER, Q, killactive                # key, [flags], mods, key, dispatcher
bind = SUPER, mouse:272, movewindow
bindm = SUPER, mouse:272, movewindow       # mouse binds
unbind = SUPER, SPACE
binde = XF86AudioRaiseVolume, exec, wpctl set-volume -l 1 @DEFAULT_AUDIO_SINK@ 5%+   # e = repeating

workspace = 1, monitor:DP-1

# 0.53+ unified windowrule: effects..., then comma, then matches
windowrule = float, class:^(kitty)$, title:^(.*)$
windowrule = opacity 1.0 override 0.5 override, class:^(kitty)$
windowrule = workspace 5 silent, class:^(firefox)$
windowrulev2 = noinitialfocus, class:^(.*)$     # pre-0.53 legacy variant

layerrule = blur, namespace:waybar
```

Old `.conf` windowrule gotchas: single rule per line, comma-separated matches
at the end, space-separated effects at the start, RE2 regex with `^(...)$`
anchoring, `class:`/`title:` prefixes. The 0.53+ "one line, comma" syntax is
what most tutorials show.

### Converting

- Prefer the in-browser converter: <https://eiontusk.github.io/hyprlang2lua/>
  (or AUR `hyprlang2lua`), then hand-check flagged/ambiguous items.
- `hyprctl eval`/the Lua REPL can be used to probe the live API while converting.
- Mapping highlights: `$var` → local variables; sections (`general {}`) →
  `hl.config({ general = {...} })`; `bind` → `hl.bind("MOD + KEY", hl.dsp... )`
  or `o.bind(...)`; `windowrule = ...` → `hl.window_rule({ match = {...}, ... })`;
  `monitor = ...` → `hl.monitor({...})`; `exec-once` → `hl.on("hyprland.start", function() hl.exec_cmd(...) end)`;
  `layerrule` → `hl.layer_rule({...})`; `animation =`/`bezier =` → `hl.animation({...})`/`hl.curve(...)`.
- **Never mix**: an old `hyprland.conf` sitting next to `hyprland.lua` is
  ignored (and can confuse), and a `.conf` in the config dir won't reload via
  the Lua engine. Convert it or remove it.

## 11. Troubleshooting workflow

Always follow this loop after touching Hyprland config:

```bash
hyprctl reload                  # force reload (config also auto-reloads on save)
hyprctl configerrors            # MUST be clean; fix errors and re-run until empty
```

- **Check which config is actually loaded**: `hyprctl version` (commit/version)
  and `hyprctl systeminfo`. Look for a stray `hyprland.conf` overriding the Lua one.
- **Lua errors on reload**: a syntax error refuses reload entirely — check the
  error popup/`hyprctl configerrors`. Runtime type errors (e.g. wrong arg shape)
  continue but log. Read `/usr/share/hypr/stubs/hl.meta.lua` for the exact
  signature of any `hl.*` call before fixing.
- **Live test snippets** (no config reload needed):
  ```bash
  hyprctl eval "return hl.version()"
  hyprctl eval "return hl.get_active_workspace().id"
  hyprctl eval "for _,w in ipairs(hl.get_windows({})) do print(w.class, w.title) end"
  hyprctl getoption general:gaps_in
  hyprctl keyword general:gaps_in 10      # runtime set; resets on reload
  ```
  The wiki documents a full interactive Lua REPL inside `hyprctl` for exploring
  the API and state.
- **Window not matching a rule**: `hyprctl clients` → compare the exact
  `class`/`title` (anchors matter: `class = "kitty"` is a regex, prefer
  `^(kitty)$` or `kitty.*`). Remember static effects only see initial values.
- **Rule order bugs**: last match wins; named rules beat anonymous rules.
- **Bind not firing**: `hyprctl binds` to see registered binds; check `locked`
  / `repeating` flags; in Omarchy, first `hl.unbind` the old binding.
- **Live state**: `hyprctl monitors all`, `hyprctl layers`, `hyprctl workspaces`,
  `hyprctl workspacerules`, `hyprctl clients`.
- **Omarchy-level reset** (backs up first; ask the user before running):
  `omarchy refresh hyprland`. Debug info: `omarchy debug --no-sudo --print`.
- **Logs**: `journalctl --user -u Hyprland -e` or run Hyprland with verbose
  logging for reload errors that `configerrors` misses.

### 0.56.2 quirks observed on this machine

- `hyprctl dispatch` accepts Lua dispatcher strings (`hl.dsp.*`); the old
  space-based dispatcher syntax is unreliable here.
- Config errors can be silent if a `require` path is wrong — check
  `hyprctl configerrors` after any new `require`.

## 13. Safety rules

- **Never edit `/usr/share/omarchy/default/hypr/`** — read-only; changes are
  lost on `omarchy update`. Customize via `~/.config/hypr/*.lua` instead.
- Back up before edits: `cp ~/.config/hypr/X.lua ~/.config/hypr/X.lua.bak.$(date +%s)`.
- Config reloads on save, so validate with `hyprctl reload` +
  `hyprctl configerrors` after every change; don't leave errors behind.
- Do not run `omarchy refresh hyprland` without user confirmation (it resets config).
- Lua config is arbitrary code — never paste untrusted snippets into `hyprland.lua`.

## Example requests

- "Window opens on the wrong monitor/workspace" → check `hyprctl clients`,
  look for a stale `workspace`/`monitor` window_rule, verify match regex.
- "Add a window rule to float an app" → `hl.window_rule({ match = { class = "..." }, float = true })`.
- "Make borders red for fullscreen windows" → dynamic effect `border_color` on `fullscreen = true`.
